04 / COUNT WHAT THE CORE ACTUALLY HOLDS

Bounded score buffer.
Not a total memory claim.

The inference core allocates one score list at a time, observes its actual length, and deletes it before the next block. It keeps Q/K/V projections, head outputs, a value-width numerator vector, a running maximum and normalizer, scalar temporaries, residuals and logits. Those are not hidden in the score-buffer count. Work still grows quadratically with sequence length.

Saved block traces, copied Q/K/V, full dense probability matrices, JSON reports and this page are additional audit storage. The bounded score-buffer claim applies only to forward_online without audit, not to this page's process memory, bytes, peak RSS, speed or hardware IO.

05 / NUMERICAL CONTRACT

Prior work. Clear boundaries.

Max-shifting avoids exponential overflow; tiny exponential terms may still underflow to zero. Changing block size or order changes binary64 summation and can change rounding or near-tied predictions. This is an inference backend, with no backward pass and no change to the original training or head-intervention engine.

The dense control skips future keys exactly. The legacy workbench instead uses a finite −1e30 future sentinel. Its results agree on the supplied checkpoints within tolerance, but can differ for extreme custom weights whose valid scores are even smaller. The full audit reports this legacy comparison separately. It does not silently redefine the original engine.
